# Dictation lifecycle replacement

Reference: [OpenWhispr/openwhispr at 7a6ae826](https://github.com/OpenWhispr/openwhispr/tree/7a6ae826de9ec1caf65f3a6e769475dab2ae829f), fetched 2026-10-24. Local starting revision: `cfae8a2bde1bf9436f942365497e25fbe22fec98`.

## Source findings

- Windows uses a low-level keyboard hook, emits one down/up pair, and ends the hold when the primary key or a required modifier is released. It reconciles modifier state and a missed primary-key release using `GetAsyncKeyState`. The current hook event's key state is deliberately excluded because its asynchronous state has not updated yet. See [windows-key-listener.c:191](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/resources/windows-key-listener.c#L191) and its modifier synchronization helper.
- Recording is serialized with start and stop locks. A release received while microphone startup is pending sets a stop request that is honored after startup. Preparation generations invalidate stale asynchronous work, and unsuccessful startup restores the idle state in `finally`. See [useAudioRecording.js:141](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/src/hooks/useAudioRecording.js#L141), [pending stop:261](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/src/hooks/useAudioRecording.js#L261), and [stop:314](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/src/hooks/useAudioRecording.js#L314).
- macOS differs from Windows. Its Swift helper observes Fn and modifier changes with native `NSEvent` monitors and reports Fn interruption when another key joins. Its mouse event tap explicitly recovers from disabled-tap notifications. See [macos-globe-listener.swift:257](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/resources/macos-globe-listener.swift#L257) and [keyboard monitoring:288](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/resources/macos-globe-listener.swift#L288). This is not evidence that upstream uses a Quartz keyboard tap for arbitrary shortcuts.
- The upstream [license is MIT](https://github.com/OpenWhispr/openwhispr/blob/7a6ae826de9ec1caf65f3a6e769475dab2ae829f/LICENSE). This change applies the lifecycle mechanisms in our existing Python stack. It does not vendor upstream code or binaries.

These are source observations, not an OpenWhispr runtime reliability assessment. The attempted delegated source audit produced no findings and was cancelled. The source inspection above was performed directly.

## Reproduced failures in our starting revision

1. Press Ctrl+Shift+D, press an unrelated key, release Ctrl+Shift+D. The Windows hold reports one start and zero stops while the unrelated key remains held.
2. Lose the release callback. The application remains holding a recorder even after 120 simulated seconds. The 60-second limit only bounds the PCM buffer and schedules no lifecycle stop.
3. Mouse selection during a hold still starts accessibility work and opens the selection toolbar. Three regression tests failed before the selection guards were added.
4. Microphone open/start/stop/close and initial field capture run synchronously from the UI event handler. This is a blocking path observed in source, not a measured device-driver hang.

The initial focused suite passed 48 tests despite failures 1 and 2. The full baseline ran 682 tests with 12 skipped. It failed the three new selection regressions and two existing UI tests. Both existing UI tests passed on an isolated rerun.

## Replacement contract

- Native shortcut events and physical-state reconciliation determine the hold. Unrelated keys and mouse events do not prolong it. Releasing the primary key or losing a required modifier ends it once. Physical left/right modifiers remain distinct.
- Chords with a primary key require the exact modifier set at activation. Modifier-only holds permit extra modifiers on both platforms. Auto-repeat and partial release cannot begin another hold before the required chord resets.
- Windows retains the installed native hook implementation through pynput. macOS uses a Quartz session event tap on its own run loop for dictation, with physical-state reconciliation. Unlike upstream's `NSEvent` keyboard monitors, this keeps activity delivery independent of the main thread and the selection-popup toggle. Read and rewrite tap shortcuts retain their existing monitors. The dictation tap uses `defaultTap` under the existing Accessibility grant and always returns events unchanged. `listenOnly` would require separate Input Monitoring authorization. See [Apple's event-authorization explanation at 35:32](https://developer.apple.com/videos/play/wwdc2019/701/?time=2132) and [callback run-loop placement](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)). No permission prompts or system preferences are changed.
- A worker exclusively owns each microphone session. Early release and cancellation are retained while startup is pending. The UI remains responsive during capture, open, start, stop, and close.
- Recording has a real 60-second finalization deadline. Startup and stop/close deadlines clear the UI while retaining the device ownership gate until cleanup completes. A retry cannot open an overlapping stream.
- Binding generations reject queued events from an old shortcut. Session and request generations reject old permission answers, timers, completions, and transcription results after cancellation or shutdown.
- Starting a hold invalidates pending selection reads and rewrite timers. Recording and cleanup block competing selection/playback/rewrite work. Cancellation is checked between transcription providers and before polish.
- The existing transcription providers, source order, polish setting, 0.3-second tap threshold, password checks, and clipboard safeguards remain part of acceptance. The original app/window is sampled before asynchronous preparation. The field/document/caret captured during preparation, before Listening, becomes the insertion baseline. This is deliberately not a historical key-down field snapshot. Programmatic focus changes before that capture may establish a different field within the original window. Unknown targets and changes after that baseline offer Copy.
- Every native hold gets its own activity latch before its down event reaches the UI. All mouse-button presses and unrelated keyboard activity, including repeats, invalidate automatic insertion through completion. Recording continues, and the result offers Copy. Invalidation runs directly from native callbacks and is rechecked after blocking final validation. Old binding callbacks cannot invalidate a new hold. See `STT.md` for the user-facing target rule.
- Both insertion adapters receive the captured session's cancellation predicate and check it after their final native validation, immediately before paste input. A cancelled no-input paste restores the borrowed clipboard only while its sequence remains owned. A partial native input failure is treated as potentially side-effecting and never retried automatically.
- Mac dictation requires a bounded plain-text document fingerprint. Text, UTF-16 selection range and fingerprint come from the same anchored AX element. Capture rechecks field identity and foreground PID after its state reads, and the paste boundary checks target, document and clipboard ownership again. Missing proof offers Copy. Enforcement is limited to dictation so ordinary navigation and undo remain compatible. These are bounded consistency checks, not an atomic AX-to-input transaction.
- The Mac owner loop checks trust, tap validity/enabled state, and physical keys throughout the binding lifetime, including after release. Lost observation latches activity before interrupting the hold, so pending text becomes Copy-only. Recovery cannot clear that session's latch.

## Verification boundaries

Automated checks must cover lost releases, required modifiers, unrelated input, repeat, denied permissions, release/cancel during startup, blocked device cleanup, the recording cap, stale callbacks, shortcut replacement, shutdown, cancelled provider fallback, and selection work that overlaps an entire hold. Every test invocation uses new temporary `APPDATA` and `LOCALAPPDATA` directories.

Native Windows hook and microphone checks and macOS runtime acceptance must be reported separately from mocked boundary tests. A driver call that never returns cannot safely be killed inside Python. The ownership gate intentionally prevents a second device open until that worker returns.
