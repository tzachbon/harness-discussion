# Learning from edits after dictation

Researched 2026-10-28. “WhisperFlow” and “OpenWhisper” are interpreted as **Wispr Flow** and **OpenWhispr**, consistent with this repository’s earlier OpenWhispr research. Scope: public documentation and read-only source inspection; no application execution or implementation changes.

**Both products support learning vocabulary from edits made in the destination app after dictation.** The concrete mechanism is to observe the pasted text, identify likely spelling corrections, save the corrected vocabulary, and use it in future dictations. OpenWhispr implements extraction with local algorithms and persists words; this path performs no model training. Wispr documents textbox monitoring and dictionary updates, but does not publicly specify its complete extraction algorithm.

## Wispr Flow: confirmed behavior

Wispr’s own [Data Controls](https://wisprflow.ai/data-controls) explicitly says that enabling Auto-add to Dictionary makes Flow monitor the textbox into which it pasted. Changing a transcribed word’s spelling adds it to the dictionary. This directly confirms observation of edits in the destination application, rather than requiring corrections inside Flow’s history editor.

The current [dictionary help](https://docs.wisprflow.ai/articles/4052411709-Teach-Flow-your-words-with-the-dictionary) describes automatic learning on **Mac and Windows**, controlled by an auto-learn setting. It learns selectively, announces batches, and lets users edit or remove entries. Names and specialist vocabulary are the intended use; common words, paths, URLs, code symbols, IDs and various other categories are excluded. The same article documents explicit misspelling replacements as a separate dictionary feature. Automatic learning should not be assumed to create a permanent wrong-spelling/right-spelling replacement rule.

The published sources establish vocabulary learning. They do not establish that rewriting a sentence teaches an enduring prose preference. General model improvement is another control: [data-sharing documentation](https://docs.wisprflow.ai/articles/9609615338-Private-Cloud-Sync-and-Data-Sharing-preferences-in-Wispr-Flow) distinguishes training permission from cloud storage and describes edits among content eligible for improvement when allowed. That is separate from the immediate dictionary feature.

**Unconfirmed implementation detail:** a [first-hand third-party teardown report](https://github.com/saurabhav88/EnviousWispr/issues/996) describes Wispr Flow 1.6.897 as using accessibility observation, a 60-second cap, word alignment and a cloud classifier, then sending learned vocabulary as transcription hints. The underlying teardown notes are private, and this investigation did not reproduce them. Treat its timing and classifier details as a lead, not an independently verified description of current Wispr internals. The official sources above independently confirm monitoring and dictionary learning.

## OpenWhispr: implementation traced

Inspected the official repository at [`fc786f41c91de8177ce7d9333d2834d973cc3c19`](https://github.com/OpenWhispr/openwhispr/tree/fc786f41c91de8177ce7d9333d2834d973cc3c19), committed 2026-10-28 16:00:39 UTC. These are source observations at that revision, not runtime certification of a released build.

1. **Start a short observation window after paste.** The setting defaults to enabled in [useSettings.ts:177](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/hooks/useSettings.ts#L177). After a successful, non-raw paste, the handler schedules monitoring **500 ms later**, for **30 seconds**. See [ipcHandlers.js:3627](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/ipcHandlers.js#L3627). Native macOS startup adds a further settling delay in [textEditMonitor.js:609](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/textEditMonitor.js#L609).

2. **Read changes through operating-system accessibility APIs.** On macOS, it captures the target app PID before showing its overlay, then uses an AX observer on a resolved text element. Windows reads a focused element through UI Automation and polls its value/text every 500 ms. Linux uses AT-SPI, with native polling and a Python fallback. This reads field contents; it does not need to reconstruct edited text from individual keystrokes. Sources: [macOS target capture](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/textEditMonitor.js#L109), [AX observer](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/resources/macos-text-monitor.swift#L321), [Windows monitor](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/resources/windows-text-monitor.c#L214), [Linux monitor](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/resources/linux-text-monitor.c#L343).

3. **Wait until editing pauses.** Each change resets a **1.5-second debounce**. The latest field value is compared with the original pasted text. The learner receives both strings and the current dictionary. See [edit handler](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/ipcHandlers.js#L1396).

4. **Extract likely corrections locally.** [correctionLearner.js](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/utils/correctionLearner.js#L151) tokenizes text, aligns words using longest common subsequence, and finds substitutions. Larger fields use an approximate sliding window to locate the pasted passage. It rejects substitutions exceeding half the original token count, duplicate vocabulary, corrected tokens shorter than three characters, words in an English common-word list, and pairs whose normalized Levenshtein distance exceeds 0.65. Case-only and punctuation-only changes do not add words. This is a spelling heuristic, with no LLM classifier or network call in extraction.

5. **Save the corrected word and notify the user.** The extractor returns only corrected spellings. The handler adds them with provenance `learned`, refreshes the dictionary and emits a learned-corrections notification. It does not save the original wrong word as a replacement key. See [save handler](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/ipcHandlers.js#L1439). Storage is the local SQLite dictionary in Electron’s user-data database: [database location](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/database.js#L358), [dictionary writes](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/database.js#L2681).

6. **Supply vocabulary to future inference.** Local Whisper receives dictionary context through `initialPrompt`. Supported remote paths use provider-specific `prompt` or `keywords[]` fields, subject to budgets. Cleanup prompts can also append dictionary spellings. These are inference hints, with no model-weight update in this path and no guarantee that every future occurrence is corrected. See [local transcription](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/audioManager.js#L2457), [remote transcription](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/helpers/audioManager.js#L4149), [cleanup suffix](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/config/prompts/index.ts#L57).

## Limits that affect the feature

Accessibility support determines which editors can be observed. The implementation does not bind every platform to an exact inserted-text range: Windows starts from the then-focused element, the macOS AppleScript fallback follows the PID’s currently focused field, and the [Linux Python fallback](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/resources/linux-text-monitor.py#L227) handles global text events without comparing their source with the initially captured field. “It always watches exactly the pasted region” would overstate the code.

The heuristics can miss multiword corrections and can mistake some content changes for vocabulary. Unlike Wispr’s documented exclusions, the inspected OpenWhispr extractor has no explicit URL/path/code/ID filter. This investigation did not measure learning accuracy or editor compatibility.

Local extraction also does not imply that learned vocabulary always stays on the device: remote inference can receive it, and [personal-dictionary backup sync](https://github.com/OpenWhispr/openwhispr/blob/fc786f41c91de8177ce7d9333d2834d973cc3c19/src/services/SyncService.ts#L465) has a separate consent gate.

## Implication for Harness Discussion

The demonstrated feature is a vocabulary feedback loop: a bounded post-insertion observer, conservative correction extraction, persistent words, and vocabulary context for later inference. It can work without training a speech model. Learning arbitrary writing preferences would be separate behavior; the confirmed feature does not establish that capability. No implementation or settings were changed in this investigation.
